# qdrant/

## Overview
Qdrant Vector Store — built-in implementation.

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | Qdrant Vector Store — built-in implementation. | — |
| factory.py | Core | Qdrant factory module. Manages singleton instances for embedded mode and AsyncQdrantClient creation; `evict_embedded_store` / `clear_embedded_stores` release per-path embedded singletons when throwaway volumes (isolated eval runs, shutdown) are done. Unwritable paths fall back to `:memory:` with a cache key derived from the original path (`f"{path}:memory_fallback"`) so distinct base_paths never share one in-memory instance; repeated calls re-check the fallback key before creating (singleton preserved), and `evict_embedded_store` probes both keys; `embedded_fallback_paths()` lists the data directories running on the fallback, which the doctor `VectorDB` probe reports as FAIL. If the `:memory:` fallback itself fails, the original disk error is preserved in a `RuntimeError` chain (both failures reported) | ✅ |
| collections.py | Core | Collection-lifecycle operations (`QdrantCollectionMixin` hosted by `QdrantVectorStore`). Owns single-vector `create_collection`, `create_named_vector_collection` (one vector per `names` entry, each sized from the caller's real model output), `ensure_collection`, `delete_collection`, `collection_exists`, `get_collection_info`, `list_collections`, `ensure_payload_indexes` and `backfill_epoch_timestamps`; `_create_collection_with_vectors` gives every creator the shared retry and quantization path. `ensure_collection` refuses an existing collection whose vector size differs from the requested dimension (it belongs to another embedding model, and every write into it would fail the size check); named-vector collections carry no single size, so `get_collection_info` returns `None` for them and validation is skipped. | ✅ |
| filters.py | Core | Qdrant filter builder. Converts generic dict filter syntax to Qdrant SDK Filter objects, including datetime range detection, point ID queries, MatchExcept/MatchValue, and not conditions. Hosts the module-level `point_id_for` single implementation (deterministic uuid5 re-key); id filters re-key caller-facing ids through it so `HasIdCondition` always matches the point id upsert actually stored. | ✅ |
| sparse.py | Core | Qdrant sparse-vector operations (`QdrantSparseMixin` hosted by `QdrantVectorStore`). Ensures/creates sparse-only collections (named `bm25` vector, single-shot create so concurrent 409s fail fast), upserts sparse points, and queries the named vector with server-side IDF scoring. All client access goes through `_execute` so sync (embedded) and async (remote) clients work alike. | ✅ |
| store.py | Core | Qdrant vector store implementation. Supports embedded and remote deployment modes with built-in retry and exponential backoff (a missing collection raises at once: waiting never creates it, and backing off would stall fail-open callers such as the BM25 mirror before its first backfill); hosts `QdrantCollectionMixin` (collection lifecycle) and `QdrantSparseMixin` (persistent BM25 sparse channel); `point_id_for` normalizes any id into a valid UUIDv4 point id (shared by dense and sparse upserts). Reads (`search`, `search_multi_vector`, `get`, `count`, `scroll`) treat Qdrant's `Collection X not found` as an empty result rather than an error, because collections are created lazily on their first write. `hard_close` force-closes the client when a store is evicted from the embedded singleton cache. Overrides `VectorStore.is_persistent` as `local_path != ":memory:"` — embedded stores degraded to `:memory:` report non-persistent so callers can surface the ephemeral mode. | ✅ |
