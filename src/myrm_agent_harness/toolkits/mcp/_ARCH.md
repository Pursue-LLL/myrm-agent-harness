# mcp/

## Overview
MCP toolkit: client/transport management, agent tool discovery, schema tolerance, security/OAuth, and a persistent, self-healing connection pool (one warm `ClientSession` per server, reused across setup and runtime, reconnecting transparently on transport breaks with transport-aware keepalive).

| agent.py | Core | MCP tool discovery orchestration facade (`MCPAgent`). **Not** `myrm_agent_harness.agent` — filename is MCP-domain naming only. Orchestrates multi-server tool discovery with parallel fetching; a failing server is logged and skipped while healthy servers still contribute tools (per-server fault isolation, aligned with `connection_manager` / `route_mcp_servers`), raising only when every server fails — preventing one broken server from erasing the tool surface of healthy ones. Pure result/post-processing logic lives in `result_processing.py` / `tool_processing.py` as stateless module functions; `MCPAgent` calls them directly and exposes no forwarding methods. `process_session_tools()` is the single post-processing chain (filter→**prefix**→description limit→sanitize→timeout + **output guard**→annotations) shared by persistent-session actors and one-shot enumeration. **Server-prefix isolation** (`tool_processing.prefix_tool_names`): every MCP tool is renamed to `mcp__{sanitized_server}__{tool}` — prevents silent collisions when multiple servers expose identical names, eliminates permission bypass when an MCP name matches a built-in, and makes tool origin transparent in logs/audit. Filtering (`tool_processing.apply_tool_filter`) runs *before* prefixing so `tool_include/exclude` configs use original names. **Upstream fault tolerance**: `tool_processing.wrap_tools_with_timeout` catches adapter-layer exceptions (`NotImplementedError` for `AudioContent`, `ValueError` for unknown types), returning `redact_sensitive_text`-sanitized error messages instead of crashing — prevents third-party exception messages from leaking credentials (e.g. httpx includes full URL with tokens in `HTTPStatusError.__str__()`). **Auth error detection**: the timeout wrapper catches `httpx2.HTTPStatusError(401)` from the MCP transport (with `httpx` fallback for defensive compatibility), returns a clear re-authorization message to the Agent, and notifies via `auth_notify` → runtime EventBus with redacted error detail — no new tools added, zero prompt token impact. **Output size guard + vault spill**: after normalization, text results exceeding `max_output_chars` (per-server, default 100K) are handled by an optional `OversizedResultHandler` callback (injected by the business layer) to persist the full content into ArtifactVault and return a compact summary with a `vault://` pointer; if no handler is provided or it fails, falls back to head-truncation with an informative notice — prevents oversized MCP responses from blowing up the LLM context window while preserving data accessibility via `file_read_tool(vault://)`. Result normalization lives in `result_processing.normalize_mcp_result`: it accepts the raw `CallToolResult` (SDK 2.x native shape passed through unchanged by `tool_converter._invoke`); it collapses `is_error` results into a single error `str` (error details carried in `structured_content` — SEP-2145 errorSchema envelope — are appended when not already present in the joined text blocks, deduped against mirrored JSON), maps every `ContentBlock` through `coerce_content_block`, preserves valid image blocks as native `list[dict]` for the ToolMessage multimodal pipeline, and extracts `structured_content` as a supplementary JSON text block; text-only results fall back to plain `str`. The output-size guard (`max_output_chars`) applies to **every** path: plain-string results are truncated/vault-spilled directly, and multimodal results get the same guard per text block via `truncate_multimodal_text_blocks` (image blocks untouched) so a malicious server cannot bypass the context budget by pairing a huge text block with a legitimate image. Every text block in a multimodal result is additionally wrapped by `wrap_multimodal_text_blocks` with the same `wrap_untrusted` content-boundary defense as plain string results — image blocks pass through untouched, so injection text cannot ride alongside a legitimate image past the boundary (truncation runs *before* wrapping so the `UNTRUSTED_DATA` markers stay intact). `emit_mcp_app_event` runs *after* the call-timeout window so a slow progress sink cannot burn the MCP call budget. | ✅ |
| auth_notify.py | Core | Auth-expiry callback registry (toolkit layer; no runtime imports). Runtime wires handler that publishes `MCPAuthExpiredEvent`. Applies `redact_sensitive_text` to `error_detail` at entry point to prevent credential leakage through the event chain to SSE/frontend. | ✅ |
| client.py | Core | MCP client management layer. Handles MCP server connection setup, transport config conversion, and TLS/mTLS injection for HTTP transports via an `ssl.SSLContext` (load_cert_chain) + httpx_client_factory — supports encrypted client keys, CA bundle as PEM file or capath directory, and emits actionable errors (no silent key drop, no DeprecationWarning). For stdio transports, `build_client_target` resolves `env`/`cwd` from `extra_params` via `placeholders.resolve_stdio_launch` — expanding `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` placeholders (single non-recursive textual pass) and injecting the reserved `PLUGIN_ROOT`/`PLUGIN_DATA` environment variables for plugin subprocesses (§9.1). | ✅ |
| placeholders.py | Core | MCP stdio runtime parameter resolution. `expand_placeholders` — one-pass, non-recursive expansion of the whitelisted `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` placeholders (unknown `${...}` tokens preserved verbatim; missing roots left untouched so spawn failures stay visible). `resolve_stdio_launch` — resolves the full `(command, args, env, cwd)` launch tuple for stdio servers, reading env/cwd/plugin roots from `extra_params`, expanding placeholders everywhere legal, and injecting the reserved `PLUGIN_ROOT`/`PLUGIN_DATA` environment variables into the subprocess environment when the corresponding root is configured (spec §9.1; the parser already rejects plugin env declarations naming these keys, so injection never overrides a plugin entry); `./`-relative cwd and `./`-prefixed commands imply the plugin root as cwd. | connection_manager.py | Core | MCP connection pool. Keys one warm connection per config-hash; each connection owns one `MCPSessionActor` per server (single persistent session, spawned once). Loop-aware (rebuilds on event-loop change), health-checked, TTL-recycled by actor last-activity. Actors self-heal transport breaks internally, so a pool rebuild is only the last resort once an actor's reconnect budget is exhausted. Exposes `tools_by_server` / `instructions_by_server` for setup, `call()` for direct tool invocation, `read_resource()` for MCP Apps UI resource fetching, and `refresh_server_auth()` for hot-updating auth headers after OAuth re-authorization (propagated to the actor's stored connection dict so the next reconnect uses fresh credentials). Passes `auth_provider`, `oversized_result_handler`, and `elicitation_handler` from server config to each `MCPSessionActor` at spawn. | ✅ |
| session_actor.py | Core | Persistent, self-healing MCP session actor. Enforces `scan_mcp_runtime_surface` before first tool freeze and on dynamic tool refresh. Owns one long-lived `mcp.ClientSession` in a dedicated owner task: initializes once, serves all calls serially via an internal queue (eliminating per-call subprocess spawn / re-initialization). Supports both tool invocations (`call`) and resource reads (`read_resource` for MCP Apps ext-apps UI content). On a transport break it reconnects in place with bounded backoff — rebinding executable tools to the fresh session while the agent-facing proxy objects stay stable (prefix-cache safe). Agent-facing proxies are `SafeStructuredTool` instances (`_make_proxy`), so a proxy argument named `config`/`run_manager` is never swallowed by langchain-core's `_run`/`_arun`. **Resource safety**: the `httpx2.AsyncClient` owned for headered HTTP/SSE transports is closed on *every* exit path (loop-top reconnect retries, terminal `_fail_to_start` / `_give_up_reconnecting` returns, the per-serve inner `finally`, and `close()`) — no transport client is leaked when a transport-target build fails after the HTTP client was already allocated. **Deterministic close semantics**: when `close()`'s grace window expires and the owner task is cancelled mid-call, any in-flight tool call or resource read is failed deterministically (a `RuntimeError` like `... closed during call` / `... closed during resource read`) before the cancellation propagates — a caller can never hang forever on a session that is going away. Applies per-server `host_serial` policy during tool post-processing so stateful hosts can force serial safety metadata even for read-only hints. **Dynamic tool discovery**: listens for `notifications/tools/list_changed` via `message_handler` injected into `Client`; the notification enqueues a `_REFRESH_SIGNAL` so `_refresh_tools` runs serialised in the owner task (zero locks, zero concurrency issues) — updates the execution-layer tool map while leaving prompt-facing proxies frozen (cache-stable). Both initialization and dynamic refresh paths are protected by `connect_timeout` to prevent owner-task deadlock if a server becomes unresponsive. `_resolve_tool` supports backward-compatible fallback: if a caller uses the original unprefixed name, the actor tries adding the `mcp__{server}__` prefix automatically. Remote transports (SSE/streamable_http) get a periodic in-band keepalive ping so idle connections behind LB/NAT are never silently dropped, and honor optional per-server `keepalive_interval` overrides; stdio (local pipe) is left unprobed. **Auth expiry notification**: when reconnection exhaustion or start failure is caused by auth-related errors (401/unauthorized/invalid_token), emits `MCPAuthExpiredEvent` via the framework EventBus so business layers can notify users to re-authorize — event-driven, zero coupling to GUI. **Dynamic auth refresh**: accepts optional `auth_provider` (MCPAuthProvider protocol); on each reconnect attempt, `_refresh_auth_headers` re-fetches headers from the provider so a re-authorized token is used instead of replaying stale credentials. `update_auth_headers` provides a synchronous hot-update path for the connection manager. **MCP Elicitation (MRTR)**: accepts optional `elicitation_handler` — an async callable `(server_name, message, schema) -> "accept"|"decline"|"cancel"` injected by the business layer. `_build_elicitation_callback` wraps it into an SDK-compatible `elicitation_callback` registered on `Client`; when configured the SDK advertises `ElicitationCapability` so servers can request user confirmation mid-tool-call. URL-mode elicitation (browser redirect) is explicitly declined — only form-mode is bridged to the approval UI. Timeout/exception safety: handler timeout → `cancel`, handler crash → `decline`, unexpected return value → `decline`. Without a handler the SDK default ("Elicitation not supported") applies. | ✅ |

| schema/ | Core | MCP inbound tool schema normalization sub-package. `normalize.py` — $ref resolution (`flatten_json_schema`, incl. OpenAPI 3.x `#/components/schemas/...` pointers and nested path descent; unresolvable/external refs degrade to a permissive schema; `components` container dropped after resolution), cache-stable canonicalization (`canonicalize_schema_for_cache` — deterministic key ordering for prompt prefix cache stability), schema complexity analysis (`analyze_schema_complexity`), and deep-nesting flattening to dot-path notation (`flatten_deep_schema` / `has_dot_keys` / `nest_flat_arguments`). `key_sanitize.py` — deterministic rename of non-conforming property keys (e.g. Cloudflare's `issue_class~neq`, `meta.<field>[<operator>]`) to the `^[a-zA-Z0-9_-]{1,64}$` pattern strict providers (Anthropic) require, with lockstep `required` remapping and collision-safe numeric suffixes; `restore_property_keys` reverses the rename at dispatch so original wire names reach the MCP call. The restore map is path-aware (keys are full nested paths) so a nested key that legitimately matches a renamed top-level key is never wrongly restored. Runs before deep flattening so the dot-path separator never collides. `composite.py` — property-level const-union collapsing (`collapse_const_unions` turns `anyOf`/`oneOf` unions of same-typed `const`s into `enum`, with a lone `null` branch dropped as `nullable: true` and outer metadata preserved — closed value sets from Rust/TypeScript servers stay visible to the LLM instead of degrading to bare scalars; `enum`/`const`/`default`/`examples` are data positions and never rewritten), and top-level composite flattening (`flatten_top_level_composite` merges `anyOf`/`oneOf`/`allOf` object branches into flat `properties`; `allOf` required merged conjunctively and same-name properties intersected — closed `const`/`enum` sets intersect, a closed set conjoined with an open type keeps the closed set, an empty intersection keeps the first definition; `anyOf`/`oneOf` cross-branch same-name properties keep the union of their `const`/`enum` values so discriminator fields expose every operational mode, a `const`/`enum` branch unioned with an open type widens to the open type, properties required by every branch are promoted to top-level `required`, and remaining per-branch alternatives fold into a `description` exclusivity hint excluding the promoted common fields). `coerce.py` — dynamic type coercion (`coerce_arguments_by_schema`) healing LLM hallucinated types (string "100" → int, "true" → bool, `{...}`/`[...]` literals → object/array via JSON/AST), bare-scalar → single-element array wrapping for `array` schemas (open-weight models emit `{"urls": "https://a.com"}` for `urls: array<string>`), numeric 1/0 ↔ boolean bidirectional coercion (boolean schemas accept int 0/1; integer/number schemas accept bool), a 64KB length guard on container-literal parsing (degenerate-output CPU/memory defense), strict-host required+nullable explicit-null completion (supports `nullable: true`, `const: null`, and `enum: [null]` forms), and stripping of null optional fields before MCP `call_tool` (`prepare_mcp_call_arguments`). Lightweight coercion observability counters. Full tolerance chain: $ref→const-collapse→composite-flatten→canonicalize→key-sanitize→deep-flatten→coerce→nest→wire-restore. | ✅ |
| structured_tool.py | Core | `SafeStructuredTool` — a `StructuredTool` subclass whose `_run`/`_arun` accept only `*args`/`**kwargs`, so langchain-core's keyword-only `config`/`run_manager` parameters can never swallow a same-named MCP/OpenAPI tool argument (the default `_run`/`_arun` bind `config` into their own slot and silently drop it — the MCP server then rejects the call with `Field required`). The overrides also stop `run`/`arun` from injecting a synthetic `run_manager`/`RunnableConfig` into the callable. Zero prompt-cache impact: schema/description/name untouched. Shared by MCP tools (`tool_converter.py`), MCP proxies (`session_actor.py`), and OpenAPI bridge tools (`openapi_bridge/tool_generator.py`). | ✅ |
| tool_converter.py | Core | MCP tool schema → LangChain `SafeStructuredTool` converter. Converts MCP `Tool` objects from `client.list_tools()` into `SafeStructuredTool` instances (a `StructuredTool` subclass whose `_run`/`_arun` never swallow `config`/`run_manager` arguments). Resolves `$ref`/`$defs` inline, collapses property-level `const` unions into `enum`s, and flattens top-level `anyOf`/`oneOf`/`allOf` input schemas; the normalized JSON Schema **dict** is passed through verbatim as `args_schema` — no Pydantic args model is built, so every semantic detail (`description`, `enum`, `minimum`/`maximum`, nested `properties`) reaches the LLM unchanged and runtime coercion stays in `tool_processing.sanitize_tools`' dict pipeline. `convert_to_openai_tool` serializes the dict verbatim, matching `langchain-mcp-adapters` / Hermes bridge behavior. Its coroutine passes the raw `CallToolResult` through unchanged — result normalization (is_error collapse, block coercion, multimodal passthrough, structured_content merge) is owned by `result_processing.normalize_mcp_result` in the single post-processing chain. | ✅ |
| transport.py | Core | Executor-backed MCP Stdio Transport (`ExecutorStdioTransport`): nested-sandbox stdio capability (bwrap/docker) with stdout JSON filtering, stderr draining + log rotation, robust termination. Standalone capability, not yet wired into the live pool path. | ✅ |

## Key Dependencies

- `core`
- `utils`
- `mcp>=2.0.0` — MCP SDK 2.x high-level client (`mcp.ClientSession` over `mcp.client.*_client` transport context managers). `ClientSession.list_tools()` returns `ListToolsResult` (access `.tools`). `stdio_client()` / `streamable_http_client()` / `sse_client()` yield the stream pair consumed by `ClientSession`.
- `httpx2>=2.9.1` — HTTP client for MCP SDK v2 transports (TLS/mTLS, auth headers). Coexists with `httpx` (used elsewhere in the project).
- `tool_converter.py` — Native MCP→LangChain tool bridge (no third-party adapter dependency).
