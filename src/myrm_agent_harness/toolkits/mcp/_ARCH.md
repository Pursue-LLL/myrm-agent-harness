# mcp/

## Overview
MCP toolkit: client/transport management, agent tool discovery, schema tolerance, security/OAuth, and a persistent, self-healing connection pool (one warm `Client` per server, reused across setup and runtime, reconnecting transparently on transport breaks with transport-aware keepalive).

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | MCP toolkit entry point. Aggregates client management, agent tool fetching, connection pooling, | ✅ |
| agent.py | Core | MCP tool discovery layer (`MCPAgent`). **Not** `myrm_agent_harness.agent` — filename is MCP-domain naming only. Orchestrates multi-server tool discovery with parallel fetching. `process_session_tools()` is the single post-processing chain (filter→**prefix**→description limit→sanitize→timeout + **output guard**→annotations) shared by persistent-session actors and one-shot enumeration. **Server-prefix isolation** (`_prefix_tool_names`): every MCP tool is renamed to `mcp__{sanitized_server}__{tool}` — prevents silent collisions when multiple servers expose identical names, eliminates permission bypass when an MCP name matches a built-in, and makes tool origin transparent in logs/audit. Filtering (`_apply_tool_filter`) runs *before* prefixing so `tool_include/exclude` configs use original names. **Content block coercion** (`_coerce_content_block`): guarantees only LLM-safe types (`text`, `image`) reach the API — `file` blocks (from `ResourceLink`), malformed `image`, and unknown types are gracefully degraded to `text`, preventing Anthropic/OpenAI 400 errors and session history poisoning. **Upstream fault tolerance**: `_timeout_wrapper` catches adapter-layer exceptions (`NotImplementedError` for `AudioContent`, `ValueError` for unknown types), returning `redact_sensitive_text`-sanitized error messages instead of crashing — prevents third-party exception messages from leaking credentials (e.g. httpx includes full URL with tokens in `HTTPStatusError.__str__()`). **Auth error detection**: `_timeout_wrapper` catches `httpx2.HTTPStatusError(401)` from the MCP transport (with `httpx` fallback for defensive compatibility), returns a clear re-authorization message to the Agent, and notifies via `auth_notify` → runtime EventBus with redacted error detail — no new tools added, zero prompt token impact. **Output size guard + vault spill**: after normalization, text results exceeding `max_output_chars` (per-server, default 100K) are handled by an optional `OversizedResultHandler` callback (injected by the business layer) to persist the full content into ArtifactVault and return a compact summary with a `vault://` pointer; if no handler is provided or it fails, falls back to head-truncation with an informative notice — prevents oversized MCP responses from blowing up the LLM context window while preserving data accessibility via `file_read_tool(vault://)`. `_normalize_mcp_result` applies coercion to every block, preserves valid image blocks as native `list[dict]` for ToolMessage multimodal pipeline, and extracts `structuredContent` from MCP artifacts as supplementary text blocks; text-only results fall back to plain `str`. `_extract_mcp_app_metadata` detects ext-apps `_meta.ui.resourceUri` in artifacts; `_emit_mcp_app_event` emits an SSE event via progress_sink to notify the frontend of embeddable MCP App UIs. | ✅ |
| auth_notify.py | Core | Auth-expiry callback registry (toolkit layer; no runtime imports). Runtime wires handler that publishes `MCPAuthExpiredEvent`. Applies `redact_sensitive_text` to `error_detail` at entry point to prevent credential leakage through the event chain to SSE/frontend. | ✅ |
| client.py | Core | MCP client management layer. Handles MCP server connection setup, transport config conversion, and TLS/mTLS injection for HTTP transports via an `ssl.SSLContext` (load_cert_chain) + httpx_client_factory — supports encrypted client keys, CA bundle as PEM file or capath directory, and emits actionable errors (no silent key drop, no DeprecationWarning). | ✅ |
| config.py | Config | MCP Configuration. Supports ssl_verify / client_cert / client_key / client_key_password for mTLS, first-class `headers` field for SSE/streamable_http with `{{secret:KEY}}` template reference, per-server `tool_include`/`tool_exclude` whitelist/blacklist fields + `should_register_mcp_tool()` filter function, per-server `host_serial` policy (force serial scheduling for host-stateful servers, overrides read-only parallel hints), optional per-server `keepalive_interval` override for remote transports, per-server `max_output_chars` (default 100K) output size guard preventing context blowup from oversized MCP responses, `sanitize_mcp_name_component()` for safe tool-name generation (replaces non-`[A-Za-z0-9_]` chars with `_`, collapses consecutive underscores, strips leading/trailing underscores, and falls back to `'unnamed'` for empty results — preserving `__` delimiter uniqueness), and `parse_mcp_tool_name()` / `is_mcp_tool_name()` for unambiguous `mcp__{server}__{tool}` prefix parsing. | ✅ |
| connection_manager.py | Core | MCP connection pool. Keys one warm connection per config-hash; each connection owns one `MCPSessionActor` per server (single persistent session, spawned once). Loop-aware (rebuilds on event-loop change), health-checked, TTL-recycled by actor last-activity. Actors self-heal transport breaks internally, so a pool rebuild is only the last resort once an actor's reconnect budget is exhausted. Exposes `tools_by_server` / `instructions_by_server` for setup, `call()` for direct tool invocation, `read_resource()` for MCP Apps UI resource fetching, and `refresh_server_auth()` for hot-updating auth headers after OAuth re-authorization (propagated to the actor's stored connection dict so the next reconnect uses fresh credentials). Passes `auth_provider`, `oversized_result_handler`, and `elicitation_handler` from server config to each `MCPSessionActor` at spawn. | ✅ |
| session_actor.py | Core | Persistent, self-healing MCP session actor. Enforces `scan_mcp_runtime_surface` before first tool freeze and on dynamic tool refresh. Owns one long-lived `Client` in a dedicated owner task: initializes once, serves all calls serially via an internal queue (eliminating per-call subprocess spawn / re-initialization). Supports both tool invocations (`call`) and resource reads (`read_resource` for MCP Apps ext-apps UI content). On a transport break it reconnects in place with bounded backoff — rebinding executable tools to the fresh session while the agent-facing proxy objects stay stable (prefix-cache safe). **Resource safety**: the `httpx2.AsyncClient` owned for headered HTTP/SSE transports is closed on *every* exit path (loop-top reconnect retries, terminal `_fail_to_start` / `_give_up_reconnecting` returns, the per-serve inner `finally`, and `close()`) — no transport client is leaked when a transport-target build fails after the HTTP client was already allocated. Applies per-server `host_serial` policy during tool post-processing so stateful hosts can force serial safety metadata even for read-only hints. **Dynamic tool discovery**: listens for `notifications/tools/list_changed` via `message_handler` injected into `Client`; the notification enqueues a `_REFRESH_SIGNAL` so `_refresh_tools` runs serialised in the owner task (zero locks, zero concurrency issues) — updates the execution-layer tool map while leaving prompt-facing proxies frozen (cache-stable). Both initialization and dynamic refresh paths are protected by `connect_timeout` to prevent owner-task deadlock if a server becomes unresponsive. `_resolve_tool` supports backward-compatible fallback: if a caller uses the original unprefixed name, the actor tries adding the `mcp__{server}__` prefix automatically. Remote transports (SSE/streamable_http) get a periodic in-band keepalive ping so idle connections behind LB/NAT are never silently dropped, and honor optional per-server `keepalive_interval` overrides; stdio (local pipe) is left unprobed. **Auth expiry notification**: when reconnection exhaustion or start failure is caused by auth-related errors (401/unauthorized/invalid_token), emits `MCPAuthExpiredEvent` via the framework EventBus so business layers can notify users to re-authorize — event-driven, zero coupling to GUI. **Dynamic auth refresh**: accepts optional `auth_provider` (MCPAuthProvider protocol); on each reconnect attempt, `_refresh_auth_headers` re-fetches headers from the provider so a re-authorized token is used instead of replaying stale credentials. `update_auth_headers` provides a synchronous hot-update path for the connection manager. **MCP Elicitation (MRTR)**: accepts optional `elicitation_handler` — an async callable `(server_name, message, schema) -> "accept"|"decline"|"cancel"` injected by the business layer. `_build_elicitation_callback` wraps it into an SDK-compatible `elicitation_callback` registered on `Client`; when configured the SDK advertises `ElicitationCapability` so servers can request user confirmation mid-tool-call. URL-mode elicitation (browser redirect) is explicitly declined — only form-mode is bridged to the approval UI. Timeout/exception safety: handler timeout → `cancel`, handler crash → `decline`, unexpected return value → `decline`. Without a handler the SDK default ("Elicitation not supported") applies. | ✅ |

## Key Dependencies

- `core`
- `utils`
- `mcp>=2.0.0` — MCP SDK v2 (`mcp.client.Client` unified interface, `mcp.server.MCPServer`). `Client.list_tools()` returns `ListToolsResult` (access `.tools`). `stdio_client()` / `streamable_http_client()` / `sse_client()` produce transport context managers passed directly to `Client()`.
- `httpx2>=2.5.0` — HTTP client for MCP SDK v2 transports (TLS/mTLS, auth headers). Coexists with `httpx` (used elsewhere in the project).
- `tool_converter.py` — Native MCP→LangChain tool bridge, replaces removed `langchain-mcp-adapters`.
