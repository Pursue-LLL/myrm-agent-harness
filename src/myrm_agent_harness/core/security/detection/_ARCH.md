# core/security/detection/

## Overview
Security detection modules — PII classification, content boundary marking, information leak detection, prompt injection guard, intent router, pseudonymization, and semantic element risk classification.

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | Module public exports for core security detection subsystem. | — |
| content_boundary.py | Core | Content boundary marking — wraps untrusted/tool output with Nonce-guarded delimiters and privileged tag stripping; `extract_wrapped_payload` unwraps envelopes via symmetric pairing for programmatic (PTC) consumers. | ✅ |
| entropy_scan.py | Core | Unknown-credential tier of the leak detector — `scan_high_entropy` returns random-looking tokens from free text (URLs, UUIDs, long hex digests and file paths are removed first; a token must be at least 24 ASCII characters with letters and digits, not a hex or base64 blob, not a reference to a secret per `secret_value.is_reference_token`, and at or above 4.2 bits of Shannon entropy per character); `shannon_entropy`. Consumed by `leak_detector`. | ✅ |
| instruction_shape.py | Core | Instruction-shape detector — sentence-level agent-directed shapes (guardrail bypass, unattended execution, exfiltration, spoofed approval, agent command, untrusted-channel-write) in durable content. | ✅ |
| intent_router.py | Core | Intake-stage dangerous intent router — dual-tier regex & actionability detection for mass destruction, mass exfiltration, and privilege mutation. | ✅ |
| leak_detector.py | Core | Information leak detector — identifies sensitive data patterns in text (vendor prefixes, ENV/JSON/Header context, structural formats, entropy, mnemonic seeds); earlier redactions (`[REDACTED:*]` markers, `abcdef***...wxyz` partial masks) count as placeholders, so redacted text scans clean. ENV-credential values, JSON-credential values and entropy tokens that are references to a secret (`secret_value`: call arguments, attribute chains, templates, class names, slugs, addresses, query strings) are neither flagged nor redacted. ENV assignments and JSON fields share one value rule (`_credential_value`: at least 16 characters, not a placeholder, not a reference); a JSON key may carry a prefix before the credential word (`SecretAccessKey`, `SessionToken`, `aws_secret_access_key`, `db_password`, `x-api-key`), and the value is redacted by position so a key containing the value's text stays intact. Under a prefixed key a value counts only as a single ASCII token that is not a paging handle, because such keys also name UI strings (`"setupToken": "Add GITHUB_TOKEN to the server settings"`, Chinese or Korean text) and continuation tokens the caller passes back verbatim (`NextContinuationToken`, `nextToken`, `next_token`, `nextSyncToken`: a bare `...Token` key whose last prefix word is a paging word — next, prev, page, continuation, cursor, sync, resume, start; `nextAuthToken`, `pageAccessToken` and `cursorApiKey` stay credentials); under a bare key (`token`, `passphrase`) a spaced value (`Bearer <token>`) still counts. The entropy tier lives in `entropy_scan.py`. Known limits: a value shorter than 16 characters under an ENV/JSON key is not redacted here (durable writes also run the persistence scan's assignment tier); a spaced or non-ASCII value under a prefixed key is not recognised; JSON embedded in a string with escaped quotes (`{\"key\": \"value\"}`) is not matched; credentials in absolute-URL query strings or userinfo, `curl -u` pairs and cookies carry no ENV/JSON label and absolute URLs are excluded from the entropy tier, so they are not detected here. | ✅ |
| password_heuristic.py | Core | Keyword-anchored password heuristic for secrets the leak detector misses — `find_password_spans` returns the secret's own span per keyword occurrence: a value the text introduces (`is`/`to`/`:`/`=`/`是`, judged by `secret_value_span`) else a generated-looking token nearby (4 classes among lower/upper/digit/strong symbol, within a tight window; the keyword, neighbouring capitalised words and references such as `status.HTTP_400_BAD_REQUEST` or `a-zA-Z0-9_` never win), plus numeric PIN/OTP/2FA codes anchored to keywords (a code after the keyword within a tight window, or one before it in the same clause; `#1234` issue references and years/mobile numbers never count; "pin" counts only as the acronym `PIN`, when introduced (`is`/`:`/`是`) or when the code follows it directly, since it is also a verb). Text without a keyword yields nothing. | ✅ |
| secret_value.py | Core | Secret value rules (SSOT for "secret or reference to one"). `secret_value_span` trims a raw labeled or connector value span and accepts it only when plausible (length, not numeric/field-state/mask, no code-expression brackets, no URL), not a bare name (constant, snake-case, unquoted camel-case) and not a reference. `is_reference_value` is the shared reference test: templates (`$X`, `${X}`, `%(x)s`, `{x}`, `<x>`), attribute chains whose parts are digit-free identifier-sized runs or digit-bearing constants (a `hex32.alnum16` credential or `john.Smith2024` is not one), calls on compound names, regex fragments (adjacent ranges such as `a-zA-Z0-9_`, a quantified `\s+`), the label itself (`password=password`) and bare names given as call arguments; `$` and `%` inside a value stay password characters. `is_reference_token` is the entropy-scan counterpart: a token is a reference when every piece between non-alphanumeric characters is readable (short words in lower/Capitalised/ACRONYM form with trailing digits, a number, a letter, a version tag), so identifiers, class names, constants, slugs, domains and query strings pass while one random piece (a secret behind `?token=` or `@`, a `<alnum20>.<alnum20>` credential) keeps the token a candidate; keyword-argument values are judged alone. Also `mask_markdown_emphasis`, `Span` and the symbol vocabulary. Consumed by `password_heuristic`, `persistence/secret_spans`, `leak_detector` and `entropy_scan`. Known limits: a password containing `()[]{}<>` is not recognised by the labeled-value tier (a `KEY=value` of at least 16 characters is still caught by `leak_detector`), and a letters-only unquoted camel-case value after a password key reads as a name. | ✅ |
| pii_classifier.py | Core | PII classifier — detects personally identifiable information (emails, phones, IDs, etc.). | ✅ |
| prompt_guard.py | Core | Prompt injection guard — 10 EN + 4 ZH injection categories with anti-obfuscation (leet speak, invisible Unicode, whitespace) and word-boundary precision. Two-tier score: `max_score` (every hit; audit trail and durable-store gates) vs `block_score` / `should_block` (only hits unambiguous on their own; consumed by the live-input guard and the rule-file loader, so plain role assignment like `Act as a translator` is audited but not blocked). Negated extraction verbs (`Never print the API keys`) are not reported. | ✅ |
| semantic_risk.py | Core | Semantic element risk lexicon (SSOT) — bilingual destructive/financial/account/admin/publish vocabulary classifying GUI controls (role + name) as high-risk; consumed by browser DOM and desktop AX interaction gates so all GUI channels share one identical gate vocabulary. | ✅ |
| harmful_state_detector.py | Core | Harmful psychological state detector — blocks self-harm/severe depression patterns from persistent memory storage. | ✅ |
| pseudonym_store.py | Core | Pseudonym store — persistent mapping between real values and pseudonyms. | ✅ |
| pseudonymizer.py | Core | Pseudonymizer — replaces PII with reversible pseudonyms using the pseudonym store. | ✅ |
