# core/security/detection/

## Overview
Security detection modules — PII classification, content boundary marking, information leak detection, prompt injection guard, intent router, pseudonymization, and semantic element risk classification.

## File & Submodule Index

| File | Role | Description | I/O/P |
|------|------|-------------|-------|
| __init__.py | Package | Module public exports for core security detection subsystem. | — |
| content_boundary.py | Core | Content boundary marking — wraps untrusted/tool output with Nonce-guarded delimiters and privileged tag stripping; `extract_wrapped_payload` unwraps envelopes via symmetric pairing for programmatic (PTC) consumers. | ✅ |
| custom_rules.py | Core | Custom keyword and pattern rules (SSOT for where a user-defined term sits in a text) — `custom_rules(policy, *levels)` lists the keywords and patterns a `PrivacyPolicy` has for those levels (blank entries dropped, since an empty keyword would match everywhere); `find_custom_spans` returns every non-overlapping span (leftmost, longest first) and `first_custom_span` the first hit in rule order; `ineffective_patterns` names the patterns that cannot be used (they do not compile or are too large to build). A keyword matches in any case at every occurrence, and the space of a keyword of several words stands for any run of whitespace (a line break, a tab, a no-break space: a pasted text wraps lines); an edge character of a script written with spaces (ASCII letters and digits, underscore, Latin, Greek, Cyrillic) needs a word boundary (`pin` is not in `spinners`, `pass` is not in `password123`), an edge that is Chinese, Japanese, Korean or punctuation needs none (`凤凰计划` matches inside a sentence, `project` between Chinese characters, `.env` only needs a closed tail). A pattern is a case-insensitive regular expression in the `regex` package's syntax (everything `re` accepts, plus Unicode property classes such as the Han script class, and `(?<name>...)` groups); one that does not compile, is nested too deep or has counted repeats that add more than `_MAX_REPEAT_ATOMS` atoms to what it spells out (the engine builds every copy when it compiles: `a{99999999}` would take gigabytes, `(?:a{1000}){1000}` ~300 MB; the length of a pattern is not limited by this) never matches, and a zero-length match is no span. A pattern that cannot finish a text within the time budget (`_PATTERN_TIMEOUT_SECONDS`; a backtracking blow-up would otherwise keep a worker and a CPU core busy for minutes) counts the whole text as its hit (`CustomSpan.timed_out`, kept even where it touches a marker, the remaining rules are skipped), so the text is masked instead of let through. A span touching a marker an earlier redaction or pseudonymization wrote (`[PII:phone]`, `[REDACTED:key]`, `<PHONE_NUMBER_1>`) is dropped, so applying the rules to their own output changes nothing. Consumed by `pii_classifier`, `pii_redactor` and `pseudonymizer`, so a term that is detected is a term that is masked. Known limits: keywords are matched literally (no stemming or synonyms); a pattern that sits near the time budget on a long text can hit it on one turn and not on the next, and masks the whole text on the turns it does. | ✅ |
| entropy_scan.py | Core | Unknown-credential tier of the leak detector — `scan_high_entropy` returns random-looking tokens from free text (URLs, UUIDs, long hex digests and file paths are removed first; a token must be at least 24 ASCII characters with letters and digits, not a hex or base64 blob, not a reference to a secret per `secret_value.is_reference_token`, and at or above 4.2 bits of Shannon entropy per character); `shannon_entropy`. Consumed by `leak_detector`. | ✅ |
| instruction_shape.py | Core | Instruction-shape detector — sentence-level agent-directed shapes (guardrail bypass, unattended execution, exfiltration, spoofed approval, agent command, untrusted-channel-write) in durable content. | ✅ |
| intent_router.py | Core | Intake-stage dangerous intent router — dual-tier regex & actionability detection for mass destruction, mass exfiltration, and privilege mutation. | ✅ |
| leak_detector.py | Core | Information leak detector — identifies sensitive data patterns in text (vendor prefixes, ENV/JSON/Header context, structural formats, entropy, mnemonic seeds); earlier redactions (`[REDACTED:*]` markers, the PII redactor's `[REDACTED] [PII:password]`, `abcdef***...wxyz` partial masks) count as placeholders, so redacted text scans clean. ENV-credential values, JSON-credential values and entropy tokens that are references to a secret (`secret_value`: call arguments, attribute chains, templates, class names, slugs, addresses, query strings) are neither flagged nor redacted. ENV assignments and JSON fields share one value rule (`_credential_value`: at least 16 characters, not a placeholder, not a reference); a JSON key may carry a prefix before the credential word (`SecretAccessKey`, `SessionToken`, `aws_secret_access_key`, `db_password`, `x-api-key`), and the value is redacted by position so a key containing the value's text stays intact. Under a prefixed key a value counts only as a single ASCII token that is not a paging handle, because such keys also name UI strings (`"setupToken": "Add GITHUB_TOKEN to the server settings"`, Chinese or Korean text) and continuation tokens the caller passes back verbatim (`NextContinuationToken`, `nextToken`, `next_token`, `nextSyncToken`: a bare `...Token` key whose last prefix word is a paging word — next, prev, page, continuation, cursor, sync, resume, start; `nextAuthToken`, `pageAccessToken` and `cursorApiKey` stay credentials); under a bare key (`token`, `passphrase`) a spaced value (`Bearer <token>`) still counts. The entropy tier lives in `entropy_scan.py`. Known limits: a value shorter than 16 characters under an ENV/JSON key is not redacted here (durable writes also run the persistence scan's assignment tier); a spaced or non-ASCII value under a prefixed key is not recognised; JSON embedded in a string with escaped quotes (`{\"key\": \"value\"}`) is not matched; credentials in absolute-URL query strings or userinfo, `curl -u` pairs and cookies carry no ENV/JSON label and absolute URLs are excluded from the entropy tier, so they are not detected here. | ✅ |
| password_heuristic.py | Core | Keyword-anchored password heuristic for secrets the leak detector misses — `find_password_spans` returns the secret's own span per keyword occurrence: a value the text introduces (`is`/`to`/`:`/`=`/`是`, judged by `secret_value_span`) else a generated-looking token nearby (4 classes among lower/upper/digit/strong symbol, within a tight window; the keyword, neighbouring capitalised words and references such as `status.HTTP_400_BAD_REQUEST` or `a-zA-Z0-9_` never win), plus numeric PIN/OTP/2FA codes anchored to keywords (a code after the keyword within a tight window, or one before it in the same clause; `#1234` issue references and years/mobile numbers never count; "pin" counts only as the acronym `PIN`, when introduced (`is`/`:`/`是`) or when the code follows it directly, since it is also a verb). Text without a keyword yields nothing. A label may end in the keyword (`DB_PASSWORD`) but not continue it (`passwords`, `password_hash`), and the redactor's own `[PII:password]` tag is never a label; a value stops at a quote, comma or semicolon. One definition serves two callers: `strict=True` (default, text that is stored: eight characters with a digit or symbol) and `strict=False` (text that leaves the machine, used by `pii_classifier`, `pii_redactor` and `pseudonymizer`: a value assigned with `:`/`=`/`：` counts from six characters, letters-only or numeric, so `password: 123456` is a password while `password is hunter2` and references stay out). | ✅ |
| secret_value.py | Core | Secret value rules (SSOT for "secret or reference to one"). `secret_value_span` trims a raw labeled or connector value span and accepts it only when plausible (length, not numeric/field-state/mask, no code-expression brackets, no URL; `allow_letters_only` and `allow_numeric` let a caller that knows the label names a password accept `dragonfly` or `123456`, and repeated digits are a password while repeated symbols are a mask), not a bare name (constant, snake-case, unquoted camel-case) and not a reference. `is_reference_value` is the shared reference test: templates (`$X`, `${X}`, `%(x)s`, `{x}`, `<x>`), attribute chains whose parts are digit-free identifier-sized runs or digit-bearing constants (a `hex32.alnum16` credential or `john.Smith2024` is not one), calls on compound names, regex fragments (adjacent ranges such as `a-zA-Z0-9_`, a quantified `\s+`), the label itself (`password=password`) and bare names given as call arguments; `$` and `%` inside a value stay password characters. `is_reference_token` is the entropy-scan counterpart: a token is a reference when every piece between non-alphanumeric characters is readable (short words in lower/Capitalised/ACRONYM form with trailing digits, a number, a letter, a version tag), so identifiers, class names, constants, slugs, domains and query strings pass while one random piece (a secret behind `?token=` or `@`, a `<alnum20>.<alnum20>` credential) keeps the token a candidate; keyword-argument values are judged alone. Also `mask_markdown_emphasis`, `Span` and the symbol vocabulary. Consumed by `password_heuristic`, `persistence/secret_spans`, `leak_detector` and `entropy_scan`. Known limits: a password containing `()[]{}<>` is not recognised by the labeled-value tier (a `KEY=value` of at least 16 characters is still caught by `leak_detector`), and a letters-only unquoted camel-case value after a password key reads as a name. | ✅ |
| pii_classifier.py | Core | PII classifier — detects personally identifiable information (emails, phones, IDs, etc.). A password is not a regex here: `classify_content` asks `password_heuristic.find_password_spans(strict=False)` (pattern name `password_context`). The user's custom S3 keywords and patterns (`custom_rules`) are checked first and the custom S2 ones before the built-in S2 patterns, on a text of any length (pattern names `custom_s3_keyword:<keyword>`, `custom_s2_pattern:<first 50 characters>`); the built-in detectors skip texts shorter than six characters. `contains_level(content, policy, level)` says whether a text holds something of one level (a text that reaches S3 may hold S2 content too), by the same custom-then-built-in rule as `classify_content`. `classify_tool_params` checks every string parameter, short ones included. A bank card (S3, Luhn-checked) is a number of a major network (Visa, Mastercard 51-55 and 2221-2720, UnionPay, Amex, JCB, Discover) as one run of 15-19 digits or typed with the same hyphen or space between the groups: four of four (`4532 0151 1283 0366`), UnionPay's fifth group of three (`6222 0212 3456 7890 011`), Amex as 4-6-5 (`3782 822463 10005`); an expiry date typed after the number is not part of it. A grouped number that fails the check stays a visible card (S2, `credit_card_visible`). A mainland phone number is one run of 11 digits or typed as `138 0013 8000` / `138-0013-8000` (the typed form must not follow a letter, so the tail of a UUID is not read as a number). A US number written without the country code (`(415) 555-2671`, `415-555-2671`, optionally led by `1-`; area code and exchange do not start with 0 or 1) is `us_phone`; behind a `+<country code>` the international pattern reads the number, so no number is found by both. Known limits: Diners Club, mixed separators, other separators (no-break space) and grouped ID card numbers are not matched. | ✅ |
| prompt_guard.py | Core | Prompt injection guard — 10 EN + 4 ZH injection categories with anti-obfuscation (leet speak, invisible Unicode, whitespace) and word-boundary precision. Two-tier score: `max_score` (every hit; audit trail and durable-store gates) vs `block_score` / `should_block` (only hits unambiguous on their own; consumed by the live-input guard and the rule-file loader, so plain role assignment like `Act as a translator` is audited but not blocked). Negated extraction verbs (`Never print the API keys`) are not reported. | ✅ |
| semantic_risk.py | Core | Semantic element risk lexicon (SSOT) — bilingual destructive/financial/account/admin/publish vocabulary classifying GUI controls (role + name) as high-risk; consumed by browser DOM and desktop AX interaction gates so all GUI channels share one identical gate vocabulary. | ✅ |
| harmful_state_detector.py | Core | Harmful psychological state detector — blocks self-harm/severe depression patterns from persistent memory storage. | ✅ |
| pseudonym_store.py | Core | Pseudonym store — persistent mapping between real values and pseudonyms. | ✅ |
| pseudonymizer.py | Core | Pseudonymizer — replaces PII with reversible pseudonyms using the pseudonym store. At S3 the password values found by `password_heuristic` are replaced, the label stays (`password: <PASSWORD_1>`). The user's custom keywords and patterns of the processed level (`custom_rules`) become `<CUSTOM_KEYWORD_n>` / `<CUSTOM_PATTERN_n>` tags after the built-in detectors; one tag per distinct original, so the restorer returns the original text of each occurrence. | ✅ |
